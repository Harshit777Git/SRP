# Experimental synthetic model selection — 17 November 2026

Training command: `python scripts/train_phase32_sklearn.py`. Dataset: `data/training/v2_full_runs.npz`, 800 synthetic runs, 8 simulated classes. Existing well-group partitions were preserved: 480 train, 160 calibration/model selection, 160 held-out test. Features use the APM's shared `srp-physical-pair/1.0` physical feature contract. Five tree settings and three scaled logistic settings were compared on calibration macro F1, then the selected candidate was evaluated once on the test partition. Full metrics, confusion matrix and per-class report: `data/evaluation/phase32_sklearn_grouped.json`.

The selected new candidate was scaled logistic regression (`C=1`): calibration macro F1 0.716; held-out synthetic test macro F1 **0.631**, accuracy 0.638, log loss 0.808. Incomplete fillage test recall was 0.25; traveling-valve leakage was frequently confused with pump wear. The previous remediation physics-feature candidate reported synthetic test macro F1 **0.667** on the reused grouped holdout (`data/evaluation/remediation_metrics.json`), so this new candidate does not improve the best recorded result. Its previous test score has also informed development; the holdout is no longer pristine for a final independent claim.

The new artifact `data/training/phase32_sklearn_experimental.joblib` is marked synthetic and `deployed=False`. The previous `remediation_physics_features.joblib` remains unchanged. The production classifier was not replaced. The new 57 repaired cards span 11 simulator mechanisms with few independent runs per class, and are unsuitable for a credible independent multiclass test. There are no verified real fault-labeled test wells. Deployment gates in `fault_detection/remediation.py` require macro F1 0.90, minimum precision/recall 0.85, coverage 0.70 and at least 10 real test wells; these gates are not met.

LightGBM/PyTorch training was unavailable in the current Python environment (`ModuleNotFoundError` for LightGBM and PyTorch). No field accuracy is claimed. The next valid improvement is to obtain independently labeled field strokes, hold out entire wells, and validate the weakly separated classes with additional fluid-level/intake-pressure evidence before model promotion.

## Corrected-physics complete-stroke experiment (17 November 2026)

The current `srp-forward-2.0-plunger-clearance` capture contains 1,100 complete synthetic surface/downhole pairs (100 injected records per mechanism) across 30 virtual well configurations and 507,002 telemetry rows. All injected fault severities span 10%-100%; sensor noise and bias are zero. A card-fingerprint audit found 30 duplicate groups with 70 redundant copies, so the capture has 1,030 distinct surface-card signatures. Healthy has only 30 distinct cards, not 100 independent healthy examples.

The deterministic split groups identical physical configurations and holds out whole configurations: 18 train, 6 calibration/model-selection, 6 test wells. Records with identical surface fingerprints were deduplicated within each partition. Four candidates used the exact `live_inputs()` feature path used by the APM: robust-scaled logistic regression, Extra Trees, Random Forest and histogram gradient boosting. Extra Trees was selected on calibration macro F1 (0.667; log loss 0.878). The held-out synthetic result was macro F1 **0.644**, accuracy **0.679**, log loss **0.848**, and 196 unique test cards across six virtual wells. At the existing 0.70 probability threshold, coverage was 0.444; accepted accuracy was 0.977, but probabilities are uncalibrated. These results fail the configured coverage gate (0.70), and real test wells remain zero.

The strongest test confusion was the combined plunger/traveling-valve leakage label versus standing-valve leakage (10 leakage cards predicted as standing-valve leak and 8 in the reverse direction). Healthy recall was zero on this small holdout (6 cards). These are warning signs of weak/separable-class and class-support issues, not proof of field performance. `pump_wear` and `traveling_valve_leak` are intentionally merged because component identity is not identifiable from this simulator's shared leakage observables. The experimental artifact remains `deployed=False`; no production model was replaced. See `CURRENT_PHYSICS_V2_MODEL_REPORT.md`, `data/evaluation/current_physics_v2_model_selection.json` and the immutable held-out result named in the dataset registry.

# ML root cause analysis

- V1 used only 36 independent single-stroke runs. Its tabular and CNN estimators trained on one shallow geometry, calibrated on a medium geometry and tested on a deep geometry. Depth and SPM changed together. The production SPM guard excluded the held-out operating range.
- V1's fixed engineering scales preserve the static force and stroke. The resulting magnitude shifts can dominate leakage and gas signatures when the model has training examples from only one configuration. The V2 feature calculation adds operating context and harmonic amplitudes normalized by estimated hydrostatic load.
- The V1 CNN received two time-based branches. The input grids were generated through timestamp interpolation. The V2 record also persists the original and reconstructed timestamps so replay and auditing can verify alignment. Reconstruction errors for nominal simulated cases were much smaller than the measured traveling-valve change in the native test. Additional friction and gas can increase inverse model mismatch.
- Traveling-valve leakage and pump wear enter the same modeled outflow conductance as 2e-11 and 3e-11 times severity, respectively, before viscosity scaling. Overlapping severity values can produce equivalent physics with these sensors. Separate root-cause claims for this pair are unwarranted. Weak leakage, viscosity changes and partial fillage can cause overlapping changes in the cards. The standing and traveling valve flow paths differ in the simulator. Physical observability of each leak path through two rod-end curves requires broader validation independently of the simulated labels.
- V2 varies geometry and configurations with seed-defined settings, keeps matched geometries across classes, and holds out complete geometries. Each run contributes one reconstructed card pair. Calibrated tabular probabilities, a temperature-scaled dual-branch CNN and a fixed probability average are evaluated across seeds. Synthetic fault labels remain confined to the offline runner.
- A longer dataset with multiple operating days, fault onset scenarios, additional classes excluded from training and independent field cases is still required to quantify operational false alarms, onset latency and unknown-class rejection beyond confidence abstention on the held-out classes.
